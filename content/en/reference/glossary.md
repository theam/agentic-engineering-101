# Glossary

The terms this guide uses, with the Spanish term the Spanish edition uses and a short definition. Terms are in alphabetical order. The last column points to the module that teaches the idea in depth.

Some of these words are ours (for example *ACTIVE index* or *triage ledger*). Others come from public practitioners, and we link the source the first time it matters. Tool detail that changes often lives in [Tools](tools.md), which is reviewed more often than this page.

> [!TIP]
> Missing a term, or found a definition that no longer matches practice? Open an issue or a pull request. [CONTRIBUTING.md](../../../CONTRIBUTING.md) explains how.

| English term | Spanish term | Definition | Module |
| --- | --- | --- | --- |
| ACTIVE index (`ACTIVE.md`) | índice ACTIVE (`ACTIVE.md`) | One always-loaded file, under 100 lines, with one row per parallel track: its state and its next gate. It is an index, not a log. You rewrite rows instead of appending, and you delete a row when the work ships. | [4](../04-context-is-infrastructure/README.md) |
| Agent view | vista de agentes (agent view) | A Claude Code screen, opened with `claude agents`, that lists your background sessions and shows which ones need your input. In research preview at the time of writing. See [Tools](tools.md). | [6](../06-run-sessions-in-parallel/README.md) |
| Agentic engineering | agentic engineering (ingeniería agéntica) | Software engineering where agents write most of the code and humans design the system around them: context, decomposition, verification, review and decisions. Named in a [post by Andrej Karpathy](https://x.com/karpathy/status/2019137879310836075) as professional work "with more oversight and scrutiny" than vibe coding. | [1](../01-from-chatbot-to-system/README.md) |
| Agentic loop | bucle agéntico | The cycle a coding agent runs on its own: read context, act with a tool (edit a file, run a command), look at the result, repeat until the task is done or it gets stuck. | [1](../01-from-chatbot-to-system/README.md) |
| AGENTS.md | AGENTS.md | An open-format instruction file for coding agents, placed at the repository root and optionally in subfolders (the nearest file wins). Stewarded by the Agentic AI Foundation. We use it as the one shared contract for every agent. See [agents.md](https://agents.md/). | [4](../04-context-is-infrastructure/README.md) |
| Always-fix categories | categorías que siempre se corrigen | Review findings that get fixed in the current pull request whatever its intent: security or data exposure, serious performance regressions, duplication the PR introduces, missing behavioral coverage, and deviations from documented architecture. | [7](../07-agents-review-agents/README.md) |
| Architecture drift | deriva de arquitectura | The slow loss of a system's design when many changes are each reasonable on their own but nobody checks them against the whole. Agents make it faster, because they produce plausible pull requests quickly. | [9](../09-teams-and-organizations/README.md) |
| Blast radius | radio de impacto | How much a change touches: files, modules and time. Following [Peter Steinberger](https://steipete.me/posts/just-talk-to-it), many small-radius changes can run in parallel. Large changes that don't overlap can run in parallel too, with staggered reviews; large changes that overlap run in sequence or as one track. | [5](../05-decompose-into-tracks/README.md) |
| Brains and hands | cerebro y manos | A security pattern [DHH describes](https://lexfridman.com/dhh-2/): a coordinator model (the brains) drives a sandboxed machine (the hands), so untrusted code from issues or pull requests can't reach the coordinator's credentials. | [9](../09-teams-and-organizations/README.md) |
| CLAUDE.md | CLAUDE.md | Claude Code's instruction file. [Claude Code reads CLAUDE.md, not AGENTS.md](https://code.claude.com/docs/en/memory), so our `CLAUDE.md` imports the shared file with a single `@AGENTS.md` line. | [4](../04-context-is-infrastructure/README.md) |
| Close the loop | cerrar el bucle | Give the agent a way to build, lint, run and check its own output, so it finds and fixes its mistakes before you see them. Steinberger calls it "the big secret" in [The Pragmatic Engineer podcast](https://newsletter.pragmaticengineer.com/p/the-creator-of-clawd-i-ship-code). | [3](../03-close-the-loop/README.md) |
| Close the loop by decision | cerrar el bucle por decisión | Ending a review loop once new findings are derivative: classify every open thread, reply, resolve, and file one follow-up issue, instead of pushing another round. Security findings are never discarded. | [7](../07-agents-review-agents/README.md) |
| Compaction | compactación | Summarizing a conversation to free space in the context window, either automatically near the limit or on demand (`/compact` in Claude Code and Codex). Instructions that exist only in the chat may not survive it; files on disk do. | [4](../04-context-is-infrastructure/README.md) |
| Context engineering | ingeniería de contexto | Deciding what goes into the context window. Anthropic's [definition](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): "the smallest possible set of high-signal tokens" that makes the outcome you want likely. | [4](../04-context-is-infrastructure/README.md) |
| Context window | ventana de contexto | The model's working memory for a session: the conversation, files it read, command output, instruction files and loaded skills. It fills up as you work, and results get worse as it fills. | [2](../02-one-agent-done-well/README.md) |
| Cost per merged PR | coste por PR mergeado | Agent spend for a period divided by the pull requests merged in that period. It measures outcomes, not activity. A lower number doesn't prove more value on its own; read it next to rework rate and human minutes per PR. | [8](../08-token-economics/README.md) |
| Cross-vendor review | revisión con otro proveedor | Asking a model from a different vendor to review the work, so the reviewer doesn't share the writer's blind spots. | [7](../07-agents-review-agents/README.md) |
| Decision record | registro de decisión | A short file in the knowledge base with what was decided, why, the alternatives considered and its status. When the decision changes, the record is superseded, not deleted. | [4](../04-context-is-infrastructure/README.md) |
| Degraded path | camino degradado | What you do while you wait for an answer or a resource you asked for. A good request names it, so a missing answer slows the work down instead of blocking it. | [9](../09-teams-and-organizations/README.md) |
| Derivative findings | hallazgos derivados | Review findings that are consequences of the previous round's fixes, re-raises of items already deferred, or product questions. When most findings in a round look like this, the loop has stopped converging. | [7](../07-agents-review-agents/README.md) |
| Fresh-context review | revisión con contexto limpio | A review done by a new session or subagent with no memory of the implementation, so it judges the result and not the reasoning that produced it. | [7](../07-agents-review-agents/README.md) |
| Full gate | validación local completa (full gate) | One local command that runs lint, build and every test, so the agent can verify its work before pushing instead of waiting for remote CI. | [3](../03-close-the-loop/README.md) |
| Gate | punto de control | A point where work stops until a check passes or someone decides: CI green, plan accepted, review done, merge. Human gates are the ones only a person takes: accepting a plan, moving a board state, merging, posting outside the team, running production-privileged commands. | [9](../09-teams-and-organizations/README.md) |
| Guard | guarda | A deterministic check (a script, hook, validator or CI job) that enforces a rule the same way every time. We add one when a written rule keeps being missed. | [3](../03-close-the-loop/README.md) |
| Guardrail | barrera de seguridad (guardrail) | Any mechanism that limits what an agent can do or blocks a bad outcome: permission rules, hooks, sandboxes, validators, CI checks. | [3](../03-close-the-loop/README.md) |
| Handoff pack | paquete de traspaso (handoff pack) | A document that lets a fresh session, or you a week later, continue a track: what is Verified, Believed and Open, the traps, a first step that is executable today, and a self-contained bootstrap prompt. | [5](../05-decompose-into-tracks/README.md) |
| Harness | harness | Everything around the model that turns it into a working agent: the loop, tools, permissions, instruction files, hooks and skills. Claude Code and Codex CLI are harnesses. [Mitchell Hashimoto](https://mitchellh.com/writing/my-ai-adoption-journey) calls improving it after each agent mistake "harness engineering". | [4](../04-context-is-infrastructure/README.md) |
| Headless mode | modo headless (no interactivo) | Running an agent with one prompt and no interactive session, for scripts and CI: `claude -p "…"` or `codex exec "…"`. Both vendors' docs now call it non-interactive mode. | [6](../06-run-sessions-in-parallel/README.md) |
| Hook | hook | A command the harness runs automatically at a fixed point in the agent's lifecycle: session start, before a tool call, after an edit, before the agent stops. Unlike instructions, it runs every time. See [Claude Code hooks](https://code.claude.com/docs/en/hooks). | [3](../03-close-the-loop/README.md) |
| Inner loop, context loop, outer loop | bucle interno, bucle de contexto, bucle externo | The spine of this guide. Inner: one agent doing one task well. Context: a system that remembers between sessions. Outer: many tracks in parallel, reviewed by agents. Adapted from the [three developer loops](https://itrevolution.com/articles/the-three-developer-loops-a-new-framework-for-ai-assisted-coding/) of Gene Kim and Steve Yegge. | [0](../00-start-here/README.md) |
| Issue as prompt | issue como prompt | An issue body that works on its own as the task for a fresh session: problem, evidence with `file:line`, fix sketch, acceptance criteria and what is out of scope. | [5](../05-decompose-into-tracks/README.md) |
| Kickoff prompt | prompt de arranque (kickoff prompt) | The first message of a track's session. It lists what was already checked, decisions not to re-open, repo rules, environment traps, what to report instead of fixing, when the work is done and what to report back. See the skeleton in [Prompt patterns](prompt-patterns.md). | [5](../05-decompose-into-tracks/README.md) |
| Knowledge base (KB) | base de conocimiento (knowledge base, KB) | Files in git that keep the *why* between sessions: mission, decisions, evidence, lessons, announcements. Mostly written by agents for agents. The backlog keeps the *what, when and who*. | [4](../04-context-is-infrastructure/README.md) |
| Lethal trifecta | trifecta letal | [Simon Willison's](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/) name for an agent that has access to private data, reads untrusted content and can communicate externally. An attacker can trick it into leaking data. Remove at least one of the three. | [9](../09-teams-and-organizations/README.md) |
| MCP (Model Context Protocol) | MCP (Model Context Protocol) | An open standard for connecting AI applications to external tools and data. Useful, but every connected server adds tool descriptions to the context, so we prefer a CLI when one exists. See [modelcontextprotocol.io](https://modelcontextprotocol.io/). | [8](../08-token-economics/README.md) |
| Memory entry | entrada de memoria | A saved correction, written as *Rule / Why / How to apply* and dated, so future sessions don't repeat the mistake. The first step of the promotion path. | [4](../04-context-is-infrastructure/README.md) |
| Merge order is not work order | el orden de merge no es el orden de trabajo | Tracks that depend on each other can still be worked on at the same time. Only the merges need a sequence. | [5](../05-decompose-into-tracks/README.md) |
| Mission repository | repositorio de misión | One repository whose purpose is a mission. It holds the knowledge base and links the product repositories, and planning sessions are opened there. Ours grew from [Limina](https://github.com/theam/limina). | [4](../04-context-is-infrastructure/README.md) |
| One PR, end to end | un PR de principio a fin | Delivering an issue as one pull request instead of PR1, PR2, PR3. Human review is the expensive step, and phases create coordination work. Exceptions: an irreversible step, or a half that must be deployed first. | [5](../05-decompose-into-tracks/README.md) |
| Permission modes | modos de permisos | Settings that decide what an agent may do without asking you: from approving every action, through auto-approving edits or classifier-reviewed actions, to skipping all checks (only in isolated environments). See [Claude Code permission modes](https://code.claude.com/docs/en/permission-modes). | [3](../03-close-the-loop/README.md) |
| Plan mode | modo plan | A mode in which the agent reads code and proposes a plan without editing files. You approve or correct the plan before anything changes. | [2](../02-one-agent-done-well/README.md) |
| PR intent statement | declaración de intención del PR | A short statement at the top of a pull request: what it is for and what is out of scope. It is the ruler for every review finding. | [7](../07-agents-review-agents/README.md) |
| Promotion path | ruta de promoción | How a correction hardens over time: "remember this" → memory entry → lesson → AGENTS.md rule → guard. Skills are created separately, when a repeated workflow hurts. | [4](../04-context-is-infrastructure/README.md) |
| Prompt injection | inyección de prompts (prompt injection) | Hostile instructions hidden in content the agent reads (an issue, a pull request, a web page, a tool result) that try to make it act against you. | [9](../09-teams-and-organizations/README.md) |
| Prompt request | prompt request | Steinberger's way of seeing outside pull requests: the intent and the prompts behind a change can matter more than the diff itself. | [7](../07-agents-review-agents/README.md) |
| Red/green TDD | TDD rojo/verde (red/green) | Write the test, run it and watch it fail (red), then implement until it passes (green). [Simon Willison](https://simonwillison.net/guides/agentic-engineering-patterns/red-green-tdd/) shows that the short prompt "Use red/green TDD" is enough for current agents. | [3](../03-close-the-loop/README.md) |
| Rework rate | tasa de retrabajo | The share of merged pull requests that needed a follow-up fix or revert within 7 days of merging. Count it a week after the period ends, so every pull request has had its 7 days. | [8](../08-token-economics/README.md) |
| Sandbox | sandbox | A boundary enforced by the operating system on which files and network destinations the agent's commands can reach. Inside it, the agent can work without asking; crossing it needs approval. | [3](../03-close-the-loop/README.md) |
| Session | sesión | One conversation with an agent, with its own context window and transcript. A session can be resumed, but it knows nothing about other sessions unless you give it that context. | [2](../02-one-agent-done-well/README.md) |
| Session hygiene | higiene de sesión | Start with `git fetch` and `git status`. End with commit, push, a clean tree, and removing the worktrees you created. With parallel sessions, a stale line in a shared file is read as current truth. | [6](../06-run-sessions-in-parallel/README.md) |
| Skill | skill | A packaged set of instructions (a `SKILL.md` file plus optional scripts and references) that the agent loads when it is relevant, or that you call by name. We write one when something already hurts, not in advance, because skills cost context. | [4](../04-context-is-infrastructure/README.md) |
| Slop | slop (código de baja calidad generado sin criterio) | Low-quality generated output accepted without judgment. It builds up when nobody runs refactor passes or reviews the shape of the code. | [7](../07-agents-review-agents/README.md) |
| Specialist reviewer | revisor especialista | A reviewer agent with one narrow job (security, privacy, UI consistency) that a lead reviewer calls and whose findings it merges. | [7](../07-agents-review-agents/README.md) |
| Subagent | subagente | A helper agent that a session starts for a focused task. It has its own context window and returns a summary, which keeps the main session's context small. | [6](../06-run-sessions-in-parallel/README.md) |
| Supersede, don't delete | reemplazar sin borrar (supersede) | When a decision changes, mark the old record as superseded, link the new one and keep both. The history of decisions is the asset. | [4](../04-context-is-infrastructure/README.md) |
| Token | token | The unit models read and write, and the unit that plans and APIs meter. Tokens spent re-deriving known facts or carrying bloated context are the easiest to save. | [8](../08-token-economics/README.md) |
| Track | pista de trabajo (track) | An independent stream of work, usually one issue, one branch and one pull request, that can run in parallel with others because it touches different files. | [5](../05-decompose-into-tracks/README.md) |
| Triage ledger | registro de triaje (triage ledger) | A table with one verdict per review finding (FIX_NOW, DEFER_TO_ISSUE or DISCARD) and a reason tied to the PR intent statement. | [7](../07-agents-review-agents/README.md) |
| Verification ratchet | trinquete de verificación (verification ratchet) | The rule that verification only gets tighter. Fix the change, not the check. If a required check can't run, report exactly what didn't run and why. | [3](../03-close-the-loop/README.md) |
| Vibe coding | vibe coding | Building software with an agent without looking at the implementation. [DHH](https://lexfridman.com/dhh-2/) uses that as the line between vibe coding and programming. Karpathy used the term for throwaway projects; some authors use it for all AI-assisted work, so check what a writer means. | [1](../01-from-chatbot-to-system/README.md) |
| Working agreement | acuerdo de trabajo | A short, written team agreement on how you work with agents: which board columns belong to agents and which to humans, the gates, the review policy, security rules and how you disclose AI assistance. | [9](../09-teams-and-organizations/README.md) |
| Worktree | worktree | An extra working directory of the same git repository, on its own branch, created with `git worktree add`. Our default isolation for parallel code tracks. See the [git worktree documentation](https://git-scm.com/docs/git-worktree). | [6](../06-run-sessions-in-parallel/README.md) |
| YOLO mode | modo YOLO | Running an agent with every permission prompt disabled. Acceptable only inside an isolated environment that holds no secrets. The exact flags are in [Tools](tools.md). | [3](../03-close-the-loop/README.md) |
